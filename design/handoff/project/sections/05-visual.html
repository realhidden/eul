Visual language

Native macOS, current era: system type, system materials, SF Symbols. eul adds exactly one piece of identity (the eyes) and one rule Apple doesn't enforce (numeric stability as law). Quiet, honest data — no skeuomorphic gauges, no rainbow charts.

5.1 Typography

System fonts only — SF Pro Text for UI, SF Mono nowhere except exported CSV. Every numeral that can change is set with monospacedDigit() and a width reservation for its worst case. This is law, not preference: a value flapping between digit counts must never move its neighbors (shipped bug, 1.x). Localized numerals inherit the same treatment; layouts budget 1.5× for German-class expansion.

5.2 Color — one semantic palette, two modes

Health is the only colored thing in the product. Normal state uses label colors (monochrome); elevated and critical are defined once in OKLCH, tuned per mode for contrast, and chosen to survive deuteranopia/protanopia: an amber–red pair separated by lightness as much as hue, never paired with green, and always accompanied by a shape change (right eye fills vs. both eyes fill). Charts are monochrome — data ink is label color at full strength, fills at 12% opacity. No chart ever encodes meaning in hue alone.

Memory-breakdown segments (app / wired / compressed) are differentiated by opacity steps of data.ink (100 / 55 / 30%), not hues — legible in both modes and to all color vision types.

5.3 Materials & density

The panel sits on the system popover material — translucency earns its place by anchoring the panel to the bar it came from; nowhere else. Tiles are flat quaternary fills, 10 pt radius, on an 8 pt spacing grid; panel width fixed at 360 pt. Density follows Control Center: generous enough to tap, dense enough that six tiles and a process list fit without scrolling at default text size.

5.4 Iconography

SF Symbols exclusively: cpu, memorychip, network, internaldrive, battery.75, sensor.fill, fanblades — plus the one custom mark, the eul eyes, drawn as a template glyph with filled variants for the two health states. No other custom icons exist; localization and weight-matching come free.

5.5 Motion rules

Motion is forbidden in any always-visible surface: the bar never animates — values are replaced at the cadence, the eye fills without transition — and widgets render static timeline snapshots. The panel is the one exception, and only because it is mounted just while open, so any motion costs power only while the user is looking. Its structural motion is two animations: open (180 ms ease-out, system default) and tile expand (160 ms). On top of that the panel animates value updates: numbers roll to their new value (~240 ms), bars, per-core columns and sparklines tween/morph between samples, and non-numeric figures (aux readings, the active port, process values) cross-dissolve (~200 ms). Reduce Motion removes all of it — both the structural animations and the value-update motion — snapping every value at the cadence. Nothing renders between refresh ticks anywhere but the open panel — assume the user is checking eul's CPU% with eul.
